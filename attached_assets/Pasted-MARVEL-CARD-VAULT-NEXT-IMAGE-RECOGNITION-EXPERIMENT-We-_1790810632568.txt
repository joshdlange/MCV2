MARVEL CARD VAULT — NEXT IMAGE RECOGNITION EXPERIMENT

We are stopping the current card-cropping/segmentation direction.

Do NOT continue:
- SAM
- edge/quadrilateral cropping
- reference-guided cropping
- the existing reranker
- hand-tuning the original nine cases

The goal now is to test a more appropriate coarse-to-fine visual recognition architecture for identifying a physical trading card from a real phone photo.

==================================================
BACKGROUND / FROZEN BASELINE
==================================================

Current verified broader baseline:

DINOv2-small, raw photo, approximately 3,045-card bounded index:

Top-1:
28/40 = 70.0%

Top-3:
31/40 = 77.5%

Top-10:
34/40 = 85.0%

A prior 41-case run produced essentially the same ~70% Top-1 result.

The existing reranker reduced accuracy.

SAM ViT-B:
- safe full-card isolation only about 12%
- approximately 35 seconds/image on tested CPU
- no overall recognition improvement
- therefore it is not part of the next architecture

Some apparent exact-ID failures have also been identified as duplicate physical-card records:
- Rogue #146 IDs 20279 / 530526
- Scott/Jean #147 IDs 20280 / 530527

Do not change those catalog records during this experiment.

==================================================
CORE ARCHITECTURE TO TEST
==================================================

We are testing this architecture:

RAW PHONE PHOTO
        ↓
GLOBAL VISUAL RETRIEVAL
        ↓
TOP 10–20 CANDIDATES
        ↓
LOCAL FEATURE / GEOMETRIC MATCHING
        ↓
FINAL VISUAL RANKING
        ↓
USER CONFIRMATION

The important change:

DO NOT require the card to be isolated before recognition.

The local matcher should attempt to identify corresponding card artwork/details between the raw photograph and candidate catalog reference even when the query includes:

- hands
- table/background
- binder pages
- neighboring cards
- sleeves
- top loaders
- rotation
- perspective
- moderate glare

==================================================
PHASE 2 — LOCAL GEOMETRIC VERIFICATION
==================================================

After Phase 1, select the best practical global retrieval model based primarily on:

1. physical-card Top-10/Top-20 recall
2. exact Top-1
3. latency
4. practicality

Then test LOCAL IMAGE MATCHING on its candidates.

Use:

ALIKED + LightGlue
OR
DISK + LightGlue

Prefer the option that is easiest to deploy and commercially appropriate.

Do NOT use SuperPoint unless you first verify its pretrained-weight license is appropriate for this commercial product.

The goal of local matching is NOT semantic similarity.

The goal is:

“Does this photograph contain the same visual card/image structure as this catalog reference?”

==================================================
PRECOMPUTATION
==================================================

For catalog references:

Precompute local features where technically possible.

Do not repeatedly extract the reference features for every query.

For each user photo:

1. extract query local features ONCE
2. retrieve global Top 10
3. match query features against each of those candidate references
4. perform geometric verification

Use an appropriate robust geometric estimator such as RANSAC/MAGSAC where supported.

==================================================
LOCAL MATCH EVIDENCE
==================================================

For every candidate collect evidence such as:

- number of feature matches
- number of geometric inliers
- inlier ratio
- spatial coverage of matches
- estimated homography validity
- reprojection error
- match confidence

Do NOT rank based purely on number of raw feature matches.

A candidate with many inconsistent matches should not beat a candidate with fewer but geometrically coherent matches.

Create a DEVELOPMENT-ONLY local verification score based on these measurements.

Do not tune weights individually for particular cards.

==================================================

==================================================

Run local verification using:

A. Top 5 global candidates
B. Top 10 global candidates
C. Top 20 global candidates ONLY if needed for recall analysis

We need to determine the smallest candidate pool that maintains useful accuracy.

Speed matters.

==================================================
CRITICAL FAILURE ANALYSIS
==================================================

For every global Top-1 miss classify what Stage 2 did.

Specifically report:

1. correct physical card was in candidate set and local matching promoted it to #1
2. correct card was in candidate set but local matching failed to promote it
3. local matching made a previously correct result worse
4. correct card never entered candidate set
5. duplicate/equivalent catalog record
6. same-art/different-printing ambiguity
7. insufficient local features because of glare/foil
8. other

This is critical.

We need to distinguish:

GLOBAL RETRIEVAL FAILURE

from

EXACT MATCHING FAILURE.

==================================================
PARALLELS / SAME ARTWORK
==================================================

Do NOT claim LightGlue can automatically distinguish parallels that use effectively identical artwork.

Local geometry may correctly establish:

“This is this artwork/card family.”

It may not establish:

“This is Gold rather than Rainbow.”

Report those separately.

If two candidate cards have essentially identical geometry/artwork, mark the case:

VISUAL FAMILY MATCH — EXACT VARIANT UNRESOLVED

Do not force confidence.

Do NOT add OCR or metadata yet.

First establish how far pure visual retrieval + geometric verification gets us.
