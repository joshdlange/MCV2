Build Marvel Card Vault Feed v1 with Activity, Leaderboards, Reactions, XP rewards, and Trade Feed Coming Soon.

Context:
Collector Profile Customization and avatar identity are now built. Users have selectable avatars, profile fields, and future-ready collector identity. We now want to start building social activity, but safely.

We want the Feed to make the app feel alive and also make Collector XP matter more. Feed activity should create visible social moments. Interacting with feed items should also provide a small amount of XP, but with strict anti-spam rules.

Goal:
Create a new Feed section in the app that shows meaningful collector activity, positive reactions, weekly leaderboards, and a Trade Feed coming soon tab.

This is not a freeform posting system yet.
This is not comments.
This is not Trade Block.
Feed v1 should be generated from real user activity only.

Activity feed event types:
Create support for meaningful events such as:
- user added first card
- user reached collection milestones: 50, 100, 250, 500 cards
- user created a PC Binder
- user completed a subset or set, if completion can be calculated reliably
- user earned a badge
- user reached a Collector XP level milestone
- user uploaded an image that was approved
- user shared a binder
- user came back after 30 days and earned the comeback badge

Avoid noisy events:
- Do not create feed events for every login.
- Do not create feed events for every search.
- Do not create feed events for every page view.
- Do not create feed events for every single card add after the first card unless it hits a milestone.

Feed event system:
- Add a feed_events table or equivalent if needed.
- Store:
  - user_id
  - event_type
  - event_title
  - event_body/metadata
  - related entity type/id if applicable
  - visibility
  - created_at
- Future meaningful actions should create feed events.
- Make feed events link to safe destinations where possible:
  - public profile
  - public/shared binder
  - card detail if safe
  - badge/profile page
  - PC Binder only if public/shared
- Make the feed mobile-first and visually polished.
- Use avatars, concise text, timestamp, and CTA/link where useful.

Retroactive backfill:

Reactions:
- Add positive collector-themed reactions to feed events.
- Do not add negative reactions, downvotes, meh, or poop reactions in v1.
- Suggested reactions:
  - 🔥 Fire Pull
  - ⚡ Hero Move
  - 👀 Need This
  - 🏆 Vault Worthy
- Users should be able to react to a feed item.
- Users should be able to remove/change their reaction.
- Store reactions in a durable table with:
  - feed_event_id
  - user_id
  - reaction_type
  - created_at
  - updated_at
- Prevent duplicate reaction rows from the same user on the same event.
- Show reaction counts on each feed item.

XP for Feed Interaction:
- Award a small amount of Collector XP for meaningful feed interaction.
- Suggested XP:
  - First reaction of the day: +5 XP
  - Additional reactions that day: +1 XP each
  - Daily cap for reaction XP: 10 XP
- Alternatively, if simpler:
  - +2 XP per reaction
  - Max 10 XP per day from reactions
- Award XP only when a user reacts to someone else’s feed item.
- Do not award XP for reacting to your own feed item.
- Do not award XP repeatedly for toggling/removing/re-adding the same reaction.
- If a user changes reaction type on the same event, do not award additional XP.
- If a user removes a reaction, do not subtract XP unless the existing XP system already supports clean reversal.
- Track XP source clearly as feed_reaction.
- Add XP event logging using the existing XP system/pattern.
- Keep feed XP small so it encourages engagement without becoming farmable.

Anti-spam / anti-abuse:
- Enforce one reaction per user per feed event, or one active reaction per user per feed event, whichever fits the existing design.
- Daily reaction XP cap must be enforced server-side.
- Users cannot earn feed reaction XP by reacting to their own posts.
- Users cannot earn extra XP by repeatedly changing reactions.
- Users cannot earn extra XP by deleting and re-reacting to the same feed event.
- Admin/test users should not skew leaderboards if existing admin exclusion patterns exist.
- Add reasonable rate limiting to reaction endpoint if practical.
- Do not create notifications for reactions in v1 unless explicitly approved.
