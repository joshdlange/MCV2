Different method, same image-only boundaries

Order: fresh raw DINO → raw top10 candidates → ORB binary features and RANSAC homography → project the verified reference card boundary into the query → crop or raw fallback → fresh DINO → unchanged detail reranker. Both DINO passes count toward timing. Candidate selection for homography uses geometric support only, never the correct label, card metadata or DINO similarity score.

ORB uses3000 features, Lowe ratio0.75, unique target matches and RANSAC3px. Gates require≥20 inliers, inlier ratio≥0.50, reference convex-hull coverage≥25%, inlier span≥50% in both axes, median reprojection≤3px and95th-percentile≤6px, convex in-bounds projected corners, query area15–90%, and bounded perspective/shape. Competing high-support candidates projecting different rectangles trigger ambiguity fallback. Parameters were fixed for this one method; no score-based retuning.

Reference physical boundary is a prerequisite. All63 unique raw-top10 reference images were independently inspected for their extent before matching. Only34 tightly framed complete card faces were enabled for boundary projection. Slabs, photographed scenes, large margins, store panels and uncertain watermark/framing were disabled; the outer photo extent was not blindly treated as a card rectangle. This is offline reference-image preparation, not an automatic general catalog-boundary solution. No per-query corners or correct-label-selected reference was supplied. Query crops inherit only geometric coordinates/aspect; reference colors/artwork are never pasted into the query.

OpenCV headless supplies standard ORB/RANSAC; NumPy is its numerical dependency. Package-management skill installed opencv-python-headless5.0.0.93 and numpy2.4.6 in its managed Python environment. No GUI packages, large ML models, paid APIs, production imports or model changes were added. The generated placeholder Python app was removed.
