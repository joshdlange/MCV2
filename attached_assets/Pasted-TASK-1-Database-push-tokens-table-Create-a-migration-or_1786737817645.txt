TASK 1: Database — push_tokens table

Create a migration or direct query to add this table if it doesn't exist:

CREATE TABLE IF NOT EXISTS push_tokens (
  id SERIAL PRIMARY KEY,
  user_id INTEGER NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  token TEXT NOT NULL,
  platform TEXT NOT NULL CHECK (platform IN ('ios', 'android', 'web')),
  created_at TIMESTAMP DEFAULT NOW(),
  updated_at TIMESTAMP DEFAULT NOW(),
  UNIQUE(user_id, token)
);

CREATE INDEX IF NOT EXISTS idx_push_tokens_user_id ON push_tokens(user_id);

TASK 2: Push notification service file

Create server/pushNotifications.js (or .ts if the project uses TypeScript):

- Initialize Firebase Admin SDK using FIREBASE_SERVICE_ACCOUNT_JSON 
  from environment secrets. Parse it as JSON.
- Export these functions:

  registerToken(userId, token, platform)
    - Upserts the token into push_tokens table
    - Updates updated_at on conflict

  sendPushToUser(userId, title, body, data = {})
    - Looks up all tokens for that userId from push_tokens
    - Sends via FCM using firebase-admin messaging
    - Returns { sent: N, failed: N }
    - Logs failures gracefully, does not throw

  sendPushToSegment(segment, title, body, data = {})
    - segment options: 'all', 'superhero', 'sidekick'
    - 'superhero' = users where subscription_tier = 'superhero' 
      (or however Super Hero is stored — check existing user/subscription 
      logic and match it exactly)
    - 'sidekick' = users where subscription_tier = 'sidekick'
    - 'all' = all users with tokens
    - Joins push_tokens with users table to get the right tokens
    - Sends in batches of 500 (FCM limit is 500 per multicast)
    - Returns { sent: N, failed: N, totalUsers: N }
    - Logs failures gracefully, does not throw

  getPushLogs(limit = 50)
    - Returns recent records from push_logs table (see Task 3)

TASK 3: push_logs table

Create this table for audit/history:

  title TEXT NOT NULL,
  body TEXT NOT NULL,
  sent_count INTEGER DEFAULT 0,

TASK 4: API Routes

Add these routes to the existing Express router. Protect admin routes 
with the existing admin auth middleware (whatever is already used for 
other admin routes — match that pattern exactly):

PUBLIC (no auth required — called by the app on device):

POST /api/push/register-token
  Body: { token: string, platform: 'ios' | 'android' | 'web' }
  - Requires user to be logged in (use existing session/auth middleware)
  - Calls registerToken(userId, token, platform)
  - Returns { success: true }
  - Returns { success: false, error } on failure

ADMIN ONLY (use existing admin auth middleware):

POST /api/admin/push/send
  Body: { 
    target: 'all' | 'superhero' | 'sidekick' | 'user',
    userId?: number,      (required only if target = 'user')
    title: string,
    body: string
  }
  - Validates all fields
  - Calls appropriate send function
  - Writes a record to push_logs
  - Returns { success: true, sent: N, failed: N }

GET /api/admin/push/logs
  - Returns last 50 push_logs records, newest first
  - Joins with users table to show admin name who sent

GET /api/admin/push/stats
  - Returns:
    {
      totalTokens: N,
      ioTokens: N,
      androidTokens: N,
      usersWithTokens: N
    }
