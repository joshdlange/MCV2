6. BUILD A DEVELOPMENT-ONLY CARD NORMALIZATION PIPELINE

After the raw-photo DINO baseline is complete, implement automatic card isolation for development testing only.

Goal:
Given a real card photo, identify the actual rectangular trading card and remove irrelevant surroundings before recognition.

The system should:

- detect the card rectangle
- identify the four corners where possible
- exclude surrounding:
  - hand
  - fingers
  - table
  - playmat
  - background
  - nearby objects
- perspective-correct the detected card
- rotate it upright
- preserve artwork proportions
- normalize the result to an approximately 2:3 portrait trading-card canvas
- do NOT stretch the artwork

Important:
The physical card boundary should be detected FIRST.

Then:
- perspective rectify
- preserve natural proportions
- normalize/pad/crop conservatively to 2:3

Do not simply force-resize the whole image to 2:3.

7. SLEEVE / TOPLOADER HANDLING

If a sleeve or top loader is present:
- try to detect the inner actual card boundary, not just the outer plastic
- if inner-card detection is unreliable, do not guess aggressively
- fall back safely

Do not let a top loader become the recognized “card rectangle” if the actual card can be identified inside it.

8. SAFE FALLBACK

If automatic boundary detection confidence is poor:
- preserve the raw image
- preserve existing manual crop capability
- do not silently cut off part of the card
- mark normalization as low-confidence/failed for that case

The normalization pipeline must fail safe.

9. KEEP THIS LIGHTWEIGHT

Do not add a heavy vision framework unless there is measured evidence it is required.

Prefer a lightweight approach first using available image-processing/computer-vision methods:
- edge detection
- contour detection
- quadrilateral detection
- perspective transform

If Sharp alone is insufficient, explain the smallest safe dependency required before adding it.

Do not add a large ML detection model just to find rectangles unless the lightweight approach clearly fails.
