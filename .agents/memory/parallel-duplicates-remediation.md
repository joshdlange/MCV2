---
name: Parallel duplicates remediation
description: Duplicate-card parallels often already exist in the matching parallel subset — moving them creates duplicates; merge is needed instead.
---

Rule: when moving "(Gold)"-style parallel cards from a base subset into their matching parallel subset, ~1/3 of them **already exist** in the target subset (same character, same number). A collision guard on target set_id+card_number is mandatory; blocked moves usually mean "redundant copy — needs cross-subset merge," not a bug.

**Why:** Measured on dev data (July 2026): of ~2,500 matched parallel groups, ~820 were clean moves, ~875 were redundant copies already present in the target, ~800 targets were occupied by a *different* card (needs eyes).

**How to apply:** DEV CLEANUP DONE (July 2026): one-time batch (`scripts/parallel-cleanup-batch.ts`, dry-run default, `--confirm` to apply) merged 876 redundant copies via `mergeRedundantParallels` (survivor found by number + normalized name in target; transfers collections/wishlists/binders then soft-archives) and moved 745 clean parallels. **The batch must be run repeatedly until moved=0** — moves free/consume slots, so the ready set shifts between passes (took 4 runs). Remaining buckets (target_occupied ~858, no-match ~1,490) are manual-review only. PROD CLEANUP DONE (July 30, 2026): 876 merged, 586 moved across 3 runs; final dry run shows 0 redundant / 0 ready. Remaining prod buckets (~279 target_occupied move-skips + no-match) are manual-review only. UNASSIGNED GROUPS (July 31, 2026): the 324 "(unassigned)" eternals parallels were 100% redundant copies — after assigning `main_set_id` to the orphan subsets, ALL classified `already_in_target` and merged (0 moves). Lesson: "(unassigned) main set" rows can't be matched by the report at all; fix `main_set_id` on the card_sets rows first, then re-run the report — never move by name guess. Note the merge guard also refuses inactive target subsets. Keep the patterns: in-tx revalidation under `pg_advisory_xact_lock(hashtext('data_quality_parallel_moves'))`; whole-token tiered subset matching, never substring ("Red" matches inside "Sacred").

**Eternals family fully consolidated (July 2026):** legacy set 1617 retired in dev AND prod — 324 parallels + 100 base merged, 15 SPs (#101-115) moved into the base subset (base checklists can run past the "100-card" subset count; parallels' 115 confirmed it). Lesson: duplicate groups containing differently-named cards (e.g. a "Hobby Box" product record sharing #1) never classify OK_PARALLEL, so their parallels are silently skipped by buildParallelSubsetReport — sweep bracketed leftovers explicitly after the report-driven pass. Sealed-product records (Hobby Box) are not cards; leave them in the inactive legacy set rather than forcing them into a card subset.
